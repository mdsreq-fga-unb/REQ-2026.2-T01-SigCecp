### RF03: Cadastrar turma

[Ver no painel do escopo](../../../painel.md#RF03)

| Campo | Descrição |
| :--- | :--- |
| **Estado e versão** | Validado, v1.3 |
| **CP de origem** | CP1: Gestão e acompanhamento de turmas (ver [2.3](../../contexto/2_solucao_proposta.md)) |
| **Declaração** | Deve ser possível à coordenação cadastrar turmas. |
| **Ator principal** | Coordenação |
| **Valor de negócio (MoSCoW)** | 3, Deveria ter · MVP (ver [priorização](../../../historico/priorizacao_geral_e_mvp.md)) |
| **Entradas** | Modalidade; dias da semana; horário de início; horário de término. Todos obrigatórios, como no protótipo apresentado em 10/11/2026. Nome da turma e instrutor não fazem parte do protótipo; não há limite de alunos por turma ([DEC24](../../../painel.md#DEC24)) |
| **Pré-condições** | Coordenador autenticado |
| **Processamento** | Valida os campos obrigatórios e grava a turma |
| **Saídas** | Turma disponível para associação de alunos e exibida na lista de turmas (modalidade, dias, horário e quantidade de alunos); mensagem indicando o campo obrigatório ausente |
| **Regras de negócio** | [RN22](../../../painel.md#RN22): o sistema inicia vazio, então cadastrar turma é a primeira ação necessária. |
| **RNFs aplicáveis** | [RNF01](../rnf/RNF01.md), [RNF03](../rnf/RNF03.md), [RNF06](../rnf/RNF06.md), [RNF11](../rnf/RNF11.md) (definições nas fichas de RNF) |
| **Critérios de aceitação** | 1. Dada uma turma com modalidade e horários, quando salva, então ela fica disponível para seleção no cadastro do aluno.<br>2. Dados campos obrigatórios ausentes, quando tenta salvar, então o sistema bloqueia e informa qual campo falta.<br>3. Dada a lista de turmas, então cada turma mostra modalidade, dias, horário e quantidade de alunos. |
| **Origem e decisões** | [DEC20](../../../painel.md#DEC20): protótipo aprovado pelo cliente em 10/11/2026; o retorno das demais pessoas do CECP também foi positivo |
