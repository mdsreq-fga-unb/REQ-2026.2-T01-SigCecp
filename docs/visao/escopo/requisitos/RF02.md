### RF02: Controlar acesso

[Ver no painel do escopo](../../../painel.md#RF02)

| Campo | Descrição |
| :--- | :--- |
| **Estado e versão** | Detalhado, v1.0 |
| **CP de origem** | Acesso e controle de usuários (ver [2.3](../../contexto/2_solucao_proposta.md)) |
| **Declaração** | O sistema deve disponibilizar as funcionalidades administrativas exclusivamente para usuários autenticados com perfil de coordenador. |
| **Ator principal** | Sistema (aplica o perfil de coordenador) |
| **Valor de negócio (MoSCoW)** | 4, Tem que ter · MVP (ver [priorização](../../../historico/priorizacao_geral_e_mvp.md)) |
| **Entradas** | Requisição a uma funcionalidade administrativa, com ou sem sessão autenticada |
| **Pré-condições** | Funcionalidade administrativa existente |
| **Processamento** | Verifica se há sessão autenticada com perfil de coordenador; se houver, libera a funcionalidade; caso contrário, nega a requisição |
| **Saídas** | Funcionalidade liberada ou acesso negado |
| **Regras de negócio** | [RN20](../../../painel.md#RN20): existe um único nível de acesso (coordenador). |
| **RNFs aplicáveis** | [RNF11](../rnf/RNF11.md), [RNF13](../rnf/RNF13.md), [RNF08](../rnf/RNF08.md) (definições nas fichas de RNF) |
| **Critérios de aceitação** | Dado um usuário autenticado com perfil de coordenador, quando acessa uma funcionalidade administrativa, então o sistema a libera.<br>Dada uma requisição sem autenticação ou sem o perfil de coordenador, quando tenta acessar uma funcionalidade administrativa, então o sistema nega o acesso. |
