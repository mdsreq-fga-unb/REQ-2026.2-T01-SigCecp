### RF01: Autenticar usuário

| Campo | Descrição |
| :--- | :--- |
| **Estado e versão** | Detalhado, v1.0 |
| **CP de origem** | Acesso e controle de usuários (ver [8.1](../../../historico/8_0_requisitos.md)) |
| **Declaração** | Deve ser possível ao coordenador acessar a área de coordenação informando usuário e senha. |
| **Ator principal** | Coordenação |
| **Valor de negócio (MoSCoW)** | 4, Tem que ter · MVP (ver [priorização](../../../historico/priorizacao_geral_e_mvp.md)) |
| **Entradas** | Usuário (formato CSCP + sequência numérica); senha |
| **Pré-condições** | Usuário previamente cadastrado ou usuário administrador padrão |
| **Processamento** | Valida usuário e senha; se corretos, inicia a sessão e libera a área de coordenação |
| **Saídas** | Acesso à área de coordenação; mensagem de erro quando as credenciais forem inválidas |
| **Regras de negócio** | [RN19](../regras_de_negocio.md#rn19): não há autocadastro; a tela de login não oferece opção de cadastro.<br>[RN20](../regras_de_negocio.md#rn20): existe um único nível de acesso (coordenador).<br>[RN21](../regras_de_negocio.md#rn21): o acesso inicial é feito por um usuário administrador padrão, entregue ao responsável do projeto, que repassa aos demais. |
| **RNFs aplicáveis** | RNF11, RNF12, RNF13 (definições em [8.2](../../../historico/8_0_requisitos.md)) |
| **Critérios de aceitação** | 1. Dados usuário e senha válidos, quando o coordenador se autentica, então o sistema libera a área de coordenação.<br>2. Dadas credenciais inválidas, quando tenta autenticar, então o sistema nega o acesso e informa o erro.<br>3. Dada a tela de login, então ela não apresenta opção de cadastro. |
