### RF18: Editar evento

[Ver no painel do escopo](../../../painel.md#RF18)

| Campo | Descrição |
| :--- | :--- |
| **Estado e versão** | Validado, v1.1 |
| **CP de origem** | CP3: Gestão de conteúdo institucional (ver [2.3](../../contexto/2_solucao_proposta.md)) |
| **Declaração** | Deve ser possível à coordenação editar os dados de um evento ou campeonato já publicado. |
| **Ator principal** | Coordenação |
| **Valor de negócio (MoSCoW)** | 3, Deveria ter · MVP (ver [priorização](../../../historico/priorizacao_geral_e_mvp.md)) |
| **Entradas** | Qualquer dado do evento (data, horário, local, descrição, informações de pagamento, mídias etc.) |
| **Pré-condições** | Coordenador autenticado; evento já publicado |
| **Processamento** | Carrega os dados atuais, aplica as alterações, revalida os campos obrigatórios e grava |
| **Saídas** | Evento atualizado exibido no módulo público |
| **Regras de negócio** | [RN26](../../../painel.md#RN26) e [RN31](../../../painel.md#RN31) (ver RF13 e RF17).<br>[RN34](../../../painel.md#RN34): a coordenação é responsável por avisar os interessados sobre alterações (por exemplo, publicando um aviso institucional); o sistema não precisa sinalizar a edição ao visitante. |
| **RNFs aplicáveis** | [RNF01](../rnf/RNF01.md), [RNF02](../rnf/RNF02.md), [RNF07](../rnf/RNF07.md), [RNF09](../rnf/RNF09.md), [RNF10](../rnf/RNF10.md) (definições nas fichas de RNF) |
| **Critérios de aceitação** | 1. Dado um evento com data incorreta, quando a coordenação corrige e salva, então a nova data é exibida no módulo público.<br>2. Dado que a coordenação esvaziou um campo obrigatório, quando tenta salvar, então o sistema bloqueia a gravação. |
