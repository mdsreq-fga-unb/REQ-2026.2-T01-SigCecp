### RF24: Inativar aluno

[Ver no painel do escopo](../../../painel.md#RF24)

| Campo | Descrição |
| :--- | :--- |
| **Estado e versão** | Detalhado, v1.0 |
| **CP de origem** | CP4: Cadastro e histórico de alunos (ver [2.3](../../contexto/2_solucao_proposta.md)) |
| **Declaração** | Deve ser possível à coordenação marcar um aluno como inativo, preservando seu histórico no sistema. |
| **Ator principal** | Coordenação |
| **Valor de negócio (MoSCoW)** | 3, Deveria ter · MVP (ver [priorização](../../../historico/priorizacao_geral_e_mvp.md)) |
| **Entradas** | Aluno; confirmação |
| **Pré-condições** | Aluno ativo; coordenador autenticado |
| **Processamento** | Exibe confirmação ("Deseja inativar [nome]?") e, ao confirmar, altera o status para inativo mantendo todos os dados |
| **Saídas** | Aluno exibido como inativo; contagem de ativos/inativos atualizada |
| **Regras de negócio** | [RN47](../../../painel.md#RN47): a inativação é manual, feita pela coordenação (ex.: aluno muito faltoso); o sistema não inativa sozinho.<br>[RN01](../../../painel.md#RN01): inativar não apaga dados nem histórico.<br>[RN48](../../../painel.md#RN48): a confirmação é exibida antes da inativação (cliente aprovou a tela de confirmação, pedida para evitar ações acidentais). |
| **RNFs aplicáveis** | [RNF03](../rnf/RNF03.md), [RNF04](../rnf/RNF04.md), [RNF05](../rnf/RNF05.md), [RNF10](../rnf/RNF10.md), [RNF11](../rnf/RNF11.md), [RNF13](../rnf/RNF13.md) (definições nas fichas de RNF) |
| **Critérios de aceitação** | 1. Dado um aluno ativo, quando a coordenação confirma a inativação, então ele passa a inativo com histórico preservado.<br>2. Dada a ação cancelada na confirmação, então o status não muda. |
| **Origem e decisões** | [DEC02](../../../painel.md#DEC02): confirmação antes de ações críticas |
